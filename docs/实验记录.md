| --- | --- | --- |

| `resultDisplay` | QLineEdit（只读） | 主显示区，显示正在输入的数据或计算结果，右对齐、34px 加粗 |
| `buttonsLayout` | QGridLayout | 4 列 × 5 行按键网格，间距 8px，`0` 占两列 |
| `hintLabel` | QLabel | 键盘操作提示；出现异常输入时改为显示提示原因 |

- 按键网格排布（4 列）：

```
C     ←     ±     ÷
7     8     9     ×
4     5     6     −
1     2     3     +
0（跨两列）  .     =
```

- 所有按钮与显示框都设为 `NoFocus`，窗口本身 `StrongFocus` 并在构造时 `setFocus()`，
  这样无论用鼠标点了哪个按钮，键盘事件都会稳定送到主窗口的 `keyPressEvent()`，不会出现

## 3. 主要代码与设计说明

结构上把「界面」与「计算」分开：

- `MainWindow`：只管界面排版、信号槽连线、键盘事件翻译；
- `CalculatorEngine`：纯逻辑状态机，不依赖任何界面类，可以脱离 GUI 单独测试。

### 3.1 按键事件处理与重复小数点

主显示区的数字文本保存在 `m_entry` 中，追加前先做校验。避免同一操作数重复输入小数点的关键代码：

```cpp
void CalculatorEngine::inputDot()
{
    m_statusMessage.clear();

    if (m_errorState) {
        clearAll();
    } else if (m_justEvaluated) {
        startFreshCalculation();
    }

    if (m_freshEntry) {                 // 刚按完运算符，从小数开始写
        m_entry = QStringLiteral("0.");
        m_freshEntry = false;
        return;
    }
    if (m_entry.contains(QLatin1Char('.'))) {   // 已含小数点则忽略
        m_statusMessage = QStringLiteral("同一个数字不能重复输入小数点");
        return;
    }
    m_entry += QLatin1Char('.');
}
```

测试结果：

| 输入 | 结果 |
| --- | --- |
| `1.2.3` | 显示 `1.23`，底部提示「同一个数字不能重复输入小数点」 |
| `5 + .` | 显示 `0.`（运算符后直接按小数点自动补 0） |
| `123` 后连按两次退格 | `1` → `0` |

### 3.2 双操作数状态管理

用一个状态机管理第一个操作数、运算符、第二个操作数与计算结果：

| 成员 | 含义 |
| --- | --- |
| `m_accumulator` | 第一个操作数（或连续运算时的中间结果） |
| `m_pendingOp` | 已按下但尚未执行的运算符 |
| `m_entry` | 当前正在输入的数（第一个或第二个操作数） |
| `m_freshEntry` | 下一次输入数字是否重新开始写（按完运算符后为 true） |
| `m_justEvaluated` | 刚按过等号，用于「计算完成后继续输入」 |
| `m_errorState` | 除零、溢出等错误状态 |

按下运算符时：若已有待执行运算符且第二个操作数已输入，就先结算前一步，把结果留在
`m_accumulator`，再挂起新的运算符，从而实现连续运算；若第二个操作数还没输入，
说明用户连按了运算符，直接用新运算符覆盖旧的。

按下等号时：执行 `m_pendingOp`，把结果格式化后写回 `m_entry` 与 `m_accumulator`，
清空 `m_pendingOp`，置 `m_justEvaluated = true`。

### 3.3 连续操作与边界处理（3 个异常/边界记录）

| # | 测试输入 | 修改前现象 | 原因分析 | 修改方法 | 修改后结果 |
| --- | --- | --- | --- | --- | --- |
| 1 | `1.2.3` | 显示 `1.2.3`，但内部 `toDouble()` 解析为 `0`，参与运算结果错误 | `inputDot()` 直接追加小数点，没有检查当前操作数是否已含小数点 | 追加前用 `m_entry.contains('.')` 判断，重复输入时忽略并给出提示 | 显示 `1.23`，并提示「同一个数字不能重复输入小数点」 |
| 2 | `1 ÷ 0 =` | 显示 `inf` | `applyPendingOperation()` 未判断除数是否为 0，double 除法直接产生 inf | 判断 `rhs == 0.0` 时进入错误状态，显示「无法除以零」，主显示区变红；同时用 `std::isfinite()` 拦截溢出结果 | 显示红色「无法除以零」，表达式保留 `1 ÷ 0 =`；按数字或退格可重新开始 |
| 3 | `5 + + 8 =` | 没有提示，行为不直观 | 连按运算符时走的是「先结算再换符」分支，缺少 `m_freshEntry` 判断 | 增加 `m_freshEntry` 分支：连按运算符直接用新运算符覆盖并提示 | 提示「连续输入运算符，已替换为 +」，结果 `13` |

另外补充处理的边界情况：

| 边界输入 | 处理方式 |
| --- | --- |
| `2 × 3 = 5 + 2 =` | 按数字开始新计算；按运算符则以结果为第一操作数继续运算，结果 `7` |
| `7 + 2 × 3 + =` | 逐次结算前一步，`(7+2)=9` → `9×3=27` → `27+27=54` |
| 连续输入 17 位数字 | 只保留 15 位（与 double 十进制精度匹配）并提示 |
| 计算结果后按退格 | 保留结果并提示「结果不能退格，可直接输入数字开始新的计算」 |
| 错误状态下按退格 | 视为清除，回到 `0`，避免用户卡在错误状态 |
| `0.1 + 0.2 =` | 按 15 位有效数字格式化，显示 `0.3` 而不是 `0.30000000000000004` |
| `1 ÷ 3 =` | 显示 `0.333333333333333` |

### 3.5 键盘事件处理（与鼠标复用同一套逻辑）

鼠标与键盘是否复用同一套处理逻辑：**是**。按钮点击与键盘输入都会先翻译成统一的「输入记号」
（`"0"`…`"9"`、`"."`、`"+"`、`"−"`、`"×"`、`"÷"`、`"="`、`"BACK"`、`"CLEAR"`、`"SIGN"`），
再进入同一个 `dispatchInput()`：

```cpp
// 1) 按钮：对象名 → 记号，统一连接
connect(button, &QPushButton::clicked, this, [this, token]() { dispatchInput(token); });

// 2) 键盘：按键 → 记号，进入同一个入口
void MainWindow::keyPressEvent(QKeyEvent *event)
{
    const QString token = tokenFromKeyEvent(event);
    if (token.isEmpty()) {
        QMainWindow::keyPressEvent(event);
        return;
    }
    event->accept();
    dispatchInput(token);
}
```

`tokenFromKeyEvent()` 优先使用 `event->text()`，这样主键盘与小键盘、`Shift + =` 得到 `+`、
不同键盘布局都能自然统一；对没有可见字符的功能键（Backspace、Enter、Esc）再回退到
`event->key()` 判断。最终两者都调用 `CalculatorEngine` 的同一组方法，不存在第二套计算逻辑。

键盘测试结果：

| 按键 | 结果 |
| --- | --- |
| `1.5*2.25` 后按 Enter | 表达式 `1.5 × 2.25 =`，结果 `3.375` |
| `12.5+7.5` 后按 Enter | 结果 `20`（与鼠标点击结果一致） |
| `8/0=` | 显示「无法除以零」 |
| `12` 后 Backspace | `1` |
| Esc | 归零 |
| F9 | 结果取反 |

## 7. 实验总结（要点）

- 状态机的关键在于想清楚「下一次输入数字是接着写还是重新写」，`m_freshEntry` 与
  `m_justEvaluated` 两个标志几乎决定了所有边界行为；
- 键盘与鼠标复用同一套逻辑，最省事的做法不是让键盘去点击按钮，而是让两条路径都翻译成
  同一套输入记号，再进同一个分发函数；
- 一次性提示与持久状态要分开：提示在下次输入时清除，但 `m_errorState` 必须保留到用户
  主动清除或重新输入，否则界面会「看起来恢复了、实际还在错误状态」；
- AI 生成的代码可以先跑通主流程，但边界情况必须自己验证：本实验通过命令行探针程序
  逐条对比「输入序列 → 显示内容」，才发现 `1.2.3` 显示与内部值不一致这类隐蔽问题。
